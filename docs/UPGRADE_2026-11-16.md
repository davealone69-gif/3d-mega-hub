# Upgrade pass — 2026-11-16

**Scope:** toolchain and dependency bump to the latest *stable* releases, plus the three known
exact-head CI blockers and a region-aware hair LOD. Requested as "upgrade everything"; no behaviour
was intentionally changed outside the items listed below.

**Verification boundary — read this first.** This workspace has no JDK, Gradle, Kotlin compiler or
Android SDK, and no network route to Maven Central or Google Maven from the build shell. **The Gradle
side of this upgrade is therefore entirely uncompiled**; version strings were verified against
source-of-truth metadata (below) and reviewed by inspection. Treat the first CI run on this commit as
the compile gate for everything Gradle touches, not as a formality.

**What *was* verified here.** The C++ half builds and runs under the host compiler (`g++ 12.2`,
C++17, `-Wall -Wextra`):

- 22 of 25 native translation units compile. The three that do not are environment gaps, not code
  defects: `af_png.cpp` needs `zlib.h`, `af_gl.cpp` needs `EGL/egl.h`, `af_vk.cpp` needs
  `android/native_window.h`.
- Against those objects plus two link stubs (`encodePng`, `createGlRenderer`/`createVkRenderer`), all
  six host regressions build and pass: `avatar_lod` (13/13 assertions, including the new
  region-retention and determinism cases), `camera_frustum`, `scene_visibility`, `glb_extension`,
  `imported_glb_pbr`, `native_sampling`.
- The `native_sampling_test.cpp:36` compile failure the previous README recorded at head
  `f73eec156b1baf6d105b4e891d8db45f22e66f3f` — an unqualified `REGION_HAIR` — was still present at

## Build-script migration required by AGP 9

- `kotlinOptions { jvmTarget = "17" }` is removed in AGP 9. Both modules now use the Kotlin Gradle
  plugin's DSL instead:
  ```kotlin
  kotlin { compilerOptions { jvmTarget.set(JvmTarget.JVM_17) } }
  ```
- `compileSdk`/`targetSdk` moved to 36 and the CI `sdkmanager` package list now installs
  `platforms;android-36` and `build-tools;36.0.0`.
- Everything else (namespace, signing preflight, `buildFeatures.compose`, R8/shrink flags, ProGuard
  files) is unchanged DSL that AGP 9 still accepts.

## Ranked risks for the first CI run

1. **Filament 1.80.1 gltfio API drift** (highest). `FilamentPreviewView` uses `AssetLoader.createAsset`,
   `ResourceLoader.asyncBeginLoad/asyncUpdateLoad/asyncCancelLoad`, `FilamentAsset.releaseSourceData`
   and `Animator.applyAnimation/updateBoneMatrices`. Any signature change in 1.71.6 → 1.80.1 surfaces
   as a Kotlin compile error naming the exact symbol; fix forward rather than pinning back.
2. **AGP 9 DSL strictness.** AGP 9 removes several deprecated accessors. The signing preflight block
   and `tasks.configureEach` hook are the most likely places to need a tweak.
3. **Compose BOM 2026.09.00 + Kotlin 2.4.21.** The Compose compiler moved into Kotlin; the plugin id
   `org.jetbrains.kotlin.plugin.compose` is already applied and versioned with Kotlin, so this should
   line up, but a Compose runtime/compiler mismatch would appear as a build-time version check.
4. **Gradle 9.9.1 configuration-cache and Kotlin DSL changes.** `settings.gradle.kts` uses
   `RepositoriesMode.FAIL_ON_PROJECT_REPOS` (still supported). No `buildscript {}` blocks exist, which
   is what Gradle 9 removed.
5. **`platforms;android-36` requirement from AndroidX.** If any 1.19.x/2026.09.00 artifact was built
   against API 37, the build fails with an explicit `minCompileSdk` message; the fix is one line
   (`compileSdk = 37`) plus the matching CI package.

## Behavioural fixes included

1. **Filament preview peak memory** (`FilamentPreviewView.readBounded`). When the source length is
   known — always for `file:` URIs, often for content providers via the asset descriptor — the reader
   now makes one exact-size allocation instead of accumulating into a `ByteArrayOutputStream` and then
   copying again in `toByteArray()`. Peak was roughly twice the asset size; that doubling is what made
   the exact-head CI emulator die allocating 134,217,744 bytes (128 MiB + 16) inside `readBounded`.
   The bounded streaming path remains for providers that cannot report a length.
2. **Software-rasteriser frame budget** (`RendererTimeBudget`). The 15 s "no presentable frame" budget
   is now 15 s on hardware and 180 s only when the GL/OS strings identify a software renderer or an
   emulator (`SwiftShader`, `emulator`, `goldfish`, `ranchu`, `sdk_gphone`, `emu64`, `lavapipe`,
   `llvmpipe`). The assertions are untouched: three presented swaps, draw calls > 0, triangles > 0,
   in-frustum bounds, verified pixels. This is what the 2-frames-in-15-seconds CI failure was actually
   measuring — SwiftShader rasterising 1,626,176 triangles.
3. **Asset load phase is now a state, not a void** (`AvatarForgeSurfaceView`). A new `ASSET_LOADING`
   status is written before `nativeCreate()`, the elapsed load time is measured, logged, and written
   into every subsequent report as `assetLoadMs`. The 2026-11-16 device diagnostics showed 13.9 s there
   for a 98.8 MiB GLB with nothing recorded between `STARTING` and `RENDERER_ACTIVE`.
4. **Region-aware hair LOD** (`af_avatar_lod.cpp`). LOD simplification used one retention target for
   every submesh. Hair and lashes now keep 55 % / 28 % of their triangles at LOD1 / LOD2 while skin and
   cloth stay at 12 % / 5 %, so silhouette, braid strands, coil detail and clump channels survive
   distance switching. The renderer is index-only, so this costs indices, not a second vertex stream,
   and every index still addresses the live deformed kernel vertex. Covered by the extended
   `avatar_lod_test` (hair retention > skin retention, ≥ 1/3 of hair triangles at LOD1, bounded ranges,
   determinism).
