# Technical review (Bravo)

Reviewed on 2026-11-14 (UTC). Evidence commit: `3facc3d051aa31fed31e6087da69b1cb9fb40616`. Scope: JNI and native lifecycle, renderer correctness, GLB loading, asset integrity, memory and resources, crash risks, release readiness.

**Independence: PARTIAL.** This was a separate review pass: the code was read again from the files, and each finding was checked against CI logs, host runs or the platform source. The same agent did the integration and the review. No independent reviewer has looked at this code, so the "Bravo review" item of the definition of done stays **PARTIAL** until one has.

Severity is the reviewer's estimate. "Emulator" means Android 11 (API 30), x86_64, software GPU.

## Fixed during the review

| ID | Area | Finding | Fix | Evidence |
|---|---|---|---|---|
| F1 | Crash risk | No renderer entry point caught C++ exceptions. The renderer allocates hundreds of megabytes for a large avatar, and an exception that unwinds into the JVM aborts the app. The engine's C API had a guard; the renderer path did not. | `d9d71af`: one barrier around session creation, frame and resize turns a C++ exception into a Java exception. The render thread reports it and tears the session down. | **REAL + VERIFIED** on emulator: run 43642406837, job 132592655367: `BARRIER_EVIDENCE cppExceptionsConverted=3 processAlive=true`. A `std::runtime_error`, a `std::bad_alloc` and a thrown `int` each arrived as a Java exception with the expected text, and native code ran normally afterwards. |
| F2 | Constraint | `libafrender.so` compiled the unused Vulkan backend and linked `libvulkan.so`. The app never selects Vulkan. | `3019c3d`: the backend is built only with `-DAF_ENABLE_VULKAN=ON`. The release gate and the debug-APK gate read every library's dependencies back and fail on `libvulkan.so` in the project's libraries. | **REAL + VERIFIED**: run 43642407532, job 132592736559 (signed APK) and run 43642404867, job 132595324383 (debug APK) list the dependencies of all twelve packaged libraries; none is `libvulkan.so`. The signed APK shrank from 47,972,820 to 46,185,764 bytes. |
| F3 | Evidence | A saved renderer report could not be tied to an APK, a phone or an asset. | `30163dc`: a `build` block and `assetSha256` in both report files; three identity lines in the panel. | **REAL + VERIFIED** on emulator: `IDENTITY_CHECK … match=true` in the three emulator jobs of the evidence commit (132592643011, 132593044475, 132592655367): the APK SHA-256 the app reports for itself equals the installed file. The asset SHA-256 it reports for the bundled sample equals the file in the repository. |
| F4 | Evidence | The debug APK that goes to the phone was not inspected. Only its SHA-256 was recorded; the owner's readiness gate also asks for the application ID and the signing certificate, read from the downloaded artifact, and for a link between the artifact and the test that ran it. | `89bea2f`, `6d4449d`, `3facc3d`: the build job inspects the APK before the emulator tests; a second job downloads the published artifact on another machine, inspects it again and checks every link. A mismatch fails the job. | **REAL + VERIFIED**: run 43642404867: `APK_INSPECTION … failures=0` in the build job and again on the downloaded file, then `DOWNLOAD_VERIFY … chain_complete=true` in job 132595324383. The first run of the inspection (43641336815) failed on a signer label that newer build-tools print differently; that was a fault in the new script, fixed in `6d4449d`. |
| F5 | GLB loading | The importer's header promises that a malformed file never crashes it and refers to a fuzz harness. That harness is not in this repository, so the promise was untested here. | `89bea2f`: a host test feeds deterministic mutations of a valid GLB to the importer and checks the index and submesh ranges of every accepted file. | **REAL + VERIFIED** on a Linux host: 90,000 mutated files (three seeds) under AddressSanitizer, UndefinedBehaviorSanitizer and leak detection produced no report; 15,553 were accepted and 74,447 rejected with an error. CI runs 8,000 of them without sanitizers. Limit: the seed file has no skin, no animation and no images, so those importer paths were not exercised. |
| F6 | Renderer | If `eglInitialize` failed, teardown still called `eglTerminate`. Android counts these calls per process, so the extra call would have released a reference held by the UI toolkit or Filament. | `89bea2f`: the display handle is cleared on that path. | Found by reading the teardown against the platform source (`egl_display.cpp`: "display termination is ref-counted"). No failure was observed, and the failing path cannot be forced on the emulator, so the fix itself is **UNVERIFIED** at run time. The normal path is unchanged and passes every gate. |
| F7 | Accuracy | `ae43e0e`, from the parallel update, said OpenGL ES 3.x had removed `glGetString(GL_EXTENSIONS)`. It has not. The code change is sound: it matches whole extension names. | `6b05ee4`: comment corrected, code kept. | OpenGL ES 3.0 to 3.2 list `EXTENSIONS` as a valid `GetString` name. No measured session reports a GL error. |

## Open findings

| ID | Area | Severity | Finding | Suggested action |
|---|---|---|---|---|
| O1 | Performance | High until measured | The default generated avatar has 1.1 to 1.6 million triangles, an 83 to 117 MB GLB and 72.7 MB of texture requests, drawn with 4x MSAA, a 2048 shadow map and bloom. The emulator's 0.2 to 0.3 FPS says nothing about the phone. Earlier phone reports for the standalone AvatarForge build (2026-10-30) show 27.8 to 49.2 FPS at 300 to 417 thousand triangles with severe heat. **UNVERIFIED** | Measure on the phone first. Decide on density, MSAA and shadow size from those numbers. |
| O2 | Memory | Medium | A large avatar session holds 485 to 650 MB of native heap on the emulator, where the software GPU's memory is counted as well. The split on the phone is unknown. After the large session closed, the heap was back at about 121 MB. **UNVERIFIED** on the phone | Read "Native heap" on the phone with the default avatar. Consider releasing the CPU copy of the geometry after upload. |
| O3 | Lifecycle | Medium | The UI thread does not wait for the render thread when Android destroys the Surface. The session holds its own `ANativeWindow` reference; the frame in flight fails its swap with `0x300d` and is counted as cut off. Every emulator session that is closed mid-frame ends this way without a crash. How the phone's GPU driver behaves here is not known. **UNVERIFIED** on the phone | Phone gate step 8: leave and return, rotate, background; three times each. |
| O4 | Release | Medium | Native libraries are not stripped. Every build prints "Unable to strip the following libraries, packaging them as they are" for all six. The release APK is larger than necessary and ships symbol tables. Probable cause, not confirmed: the engine module declares `ndkVersion`, the app module does not, so the app's strip task finds no NDK. | Add `ndkVersion = "26.1.10909125"` to `app/build.gradle.kts` and compare sizes. Keep the symbols in the debug build: they make a native crash report from the phone readable. |
| O5 | Function | Medium | Avatars are static on screen. The importer does not apply a file's skeleton or clips and does not read morph targets, and the app shows a generated avatar by exporting and importing it. Every telemetry record shows `joints: 0` while generation reports 71 joints and 52 blendshapes. **MISSING** | Render the generated avatar from the live engine session, as the test-only route already does, or teach the importer to adopt skins. |
| O6 | Diagnostics | Low | Six renderer messages go to `stderr`, which Android discards: the reason a geometry was rejected, an invalid draw range and four EGL teardown failures. The counters in the report show that something failed, not why. | Send them to logcat, once per session, and add the teardown failures to the report. |
| O7 | Camera | Low | The camera distance is fitted to the surface's aspect ratio when the session starts and is not fitted again on resize. The activity handles rotation itself, so the avatar can be framed badly after the phone is rotated. | Refit in `nativeResize`. Check during phone gate step 8. |
| O8 | Camera | Low | Pinch zoom and double-tap reset have no automated test. Drag orbit has one. | Add a two-pointer gesture test. Phone gate step 6 covers them by hand. |
| O9 | Renderer | Low | A lost GL context is not recovered while the surface stays alive. The session reports the stall and keeps retrying; it is rebuilt only when the surface is recreated. | Recreate the session after a stall with a context-lost code. |
| O10 | Manifest | Low | The manifest requires OpenGL ES 3.0; the avatar renderer needs 3.1. A 3.0-only device installs the app and then reports a renderer failure for every imported GLB. | Decide whether such devices are in scope; if not, declare `0x00030001`. |
| O11 | Logging | Low | The importer logs every accessor, the first five vertices and every image at info level, in release builds too. | Lower to debug level or compile out of release builds. |
| O12 | Diagnostics | Low | The report identity hashes the installed APK once and each GLB once per session on the render thread before the import. For a 117 MB GLB that adds to the time to first frame. The cost on the phone is **UNVERIFIED**. | Read "first frame" on the phone; move the hashing after the first frame if it matters. |
| O13 | Diagnostics | Low | The debug-only PixelCopy check encodes a PNG and writes files on the UI thread once per session. | Move the encoding to a worker thread. |
| O14 | JNI | Low | Eight test-only entry points (`GeneratedAvatarRuntimeTest_*`) are compiled into the production library. Nothing in a release build binds to them. | Compile them only for test builds. |
| O15 | Asset integrity | Low | The same avatar exports to 83,430,312 bytes on a Linux host and 83,430,028 bytes on Android. Cause not investigated. **UNVERIFIED** determinism across platforms | Compare the two files chunk by chunk. |
| O16 | Geometry | Low | Left and right are named inconsistently in the generation core, and generated avatars face `−Z` where glTF expects `+Z`. The app compensates for its own files only. See [AVATAR_GEOMETRY_EVIDENCE.md](AVATAR_GEOMETRY_EVIDENCE.md). | Fix in the generator together with the quality work. |
| O17 | Release | Blocker for a store release | Production signing needs the owner's keystore. The version code is 1. **BLOCKED** | Owner action. |

## Checked and found sound

| Area | What was checked | Evidence |
|---|---|---|
| Library loading | One `System.loadLibrary` loads `libmega_hub_avatarforge.so`; its dependencies `libafrender.so` and `libafcore.so` are packaged for both ABIs. No filament-utils library is packaged or referenced. | Dependency read-back of the debug and the signed release APK; both load and render on the emulator |
| Thread ownership | Session creation, resize, camera changes, frames, metrics and destruction happen on one render thread. The UI thread sets flags and queues camera deltas under a lock. | Reading of `AvatarForgeSurfaceView.kt` |
| Session lifetime | A session is one RAII object; every failure path in creation releases the renderer, the engine and the window. Created and destroyed counts are equal after every test. | `SESSION_EVIDENCE … live=0` and `TEST_CLEANUP_EVIDENCE … live=0` in the render jobs |
| Restart | A new session starts only after the previous render thread has ended, and the UI thread never joins it. | Reading of `startRenderer()`; no ANR in any job |
| GL correctness | `glGetError()` is drained every frame; failed draws and swaps are counted. All counters are zero in every measured session. | Telemetry in the render jobs |
| Visible output | PixelCopy of the real SurfaceView after `glFinish()`, background subtracted, at least 5,000 geometry pixels required. | `PIXELS_VERIFIED` in the diagnostic and runtime jobs |
| EGL teardown | Targets, programs, buffers, textures and vertex arrays are deleted with the context current; then the context is unbound, the surface and context are destroyed and the display reference is released. Android counts display references per process, so releasing the renderer's own reference leaves the UI toolkit's intact. | Reading of `destroyAll()` and of the platform's `egl_display.cpp`; on the emulator the app's own UI kept drawing through up to four renderer sessions in one process. Filament and the avatar renderer in one process run was not exercised by a test: **UNVERIFIED** |
| Import pipeline | The copy stops at 128 MiB; the container, JSON and accessors are validated before the native importer sees the file; files live in app-private storage; temporary files are removed on failure. Remote import is HTTPS-only, validates every redirect target and follows at most eight. | Reading of `MainActivity.kt` and `RemoteGlbUrl.kt` |
| Filament route | `Filament.init()` and `Gltfio.init()` run before any Filament object exists. Resources are destroyed in dependency order, and the engine is destroyed inside `surfaceDestroyed`. | Reading of `FilamentPreviewView.kt`; emulator launch jobs |
| Minified release | The R8-minified, signed release APK installs, launches, loads the sample and submits a frame. | Run 43642407532, job 132594421344: `INSTALL=PASS`, `LAUNCH=PASS`, `GLB_LOAD=PASS`, `RENDER_FRAME=SUBMITTED` for the file with the verified SHA-256 |
| Manifest | The app requests one permission, `INTERNET`. The packaged manifest carries a second, signature-level permission that the AndroidX core library defines for its own receivers. Backups are off, cleartext traffic is limited to `localhost` and `127.0.0.1`, and the file provider is not exported. | `AndroidManifest.xml`, `network_security_config.xml`, and the manifest read back from the built APK |
| Release process | Values are read back from the built APK and AAB, never taken from Gradle output; a second clean build must match byte for byte. | Run 43642407532, job 132592736559: `verification_failures=0`; APK and AAB `REPRODUCIBLE=yes` |
